Analisi delle Specifiche: Gestione catalogo: inserire, modificare, cancellare (mantenere vincolo d'integrità referenziale) prodotti: Inserire: Dovremo creare form HTML per l'inserimento dei dati dei prodotti (nome, descrizione, prezzo, disponibilità, ecc.) e servlet/metodi DAO per salvare queste informazioni nel database. Modificare: Avremo bisogno di pagine per visualizzare i dettagli dei prodotti esistenti (probabilmente tramite una lista con link alla pagina di modifica), form precompilati con i dati attuali e servlet/metodi DAO per aggiornare le informazioni nel database. Cancellare: Dovremo implementare meccanismi (es. bottoni di eliminazione nelle liste di prodotti) e servlet/metodi DAO per rimuovere i prodotti dal database. Mantenere vincolo d'integrità referenziale: Questa è una parte cruciale. Se i prodotti sono collegati ad altre tabelle (es. ordini, categorie), dovremo assicurarci che le operazioni di cancellazione o modifica non violino queste relazioni. Questo potrebbe significare: Impedire la cancellazione di prodotti presenti in ordini esistenti. Aggiornare le chiavi esterne in modo appropriato (a seconda della logica del tuo sistema). Utilizzare i meccanismi di ON DELETE CASCADE o ON DELETE RESTRICT definiti nel database. Visualizzare gli utenti e i loro dati: Dovremo creare una pagina web (accessibile agli amministratori) per visualizzare una lista degli utenti registrati. Questa pagina dovrebbe mostrare i dati rilevanti degli utenti (nome, email, ruolo, data di registrazione, ecc.). Potrebbe essere utile implementare funzionalità di paginazione e/o filtri per gestire grandi quantità di utenti. La visualizzazione dei "loro dati" potrebbe includere anche informazioni correlate come gli ordini effettuati da ciascun utente. Visualizzare gli ordini di tutti i clienti, per cliente e dalla data alla data: Visualizzare gli ordini di tutti i clienti: Creare una pagina web (accessibile agli amministratori) che mostri una lista di tutti gli ordini effettuati nel sistema, con dettagli come ID ordine, cliente, data, totale, stato, ecc. Per cliente: Implementare la possibilità di filtrare o visualizzare gli ordini specifici di un determinato cliente (es. tramite un form di selezione del cliente). Dalla data alla data: Implementare la possibilità di filtrare gli ordini in base a un intervallo di date (es. tramite due campi per la selezione della data iniziale e finale). Controllo accessi - pagine amministratore visibili solo all'amministratore - usare i filtri: Dovremo implementare un sistema di autenticazione e autorizzazione. Quando un utente effettua il login, il suo ruolo (es. amministratore, venditore, cliente) dovrebbe essere memorizzato nella sessione. Utilizzeremo dei filtri Servlet per intercettare le richieste alle pagine destinate agli amministratori. Questi filtri verificheranno se l'utente nella sessione ha il ruolo di amministratore. Se non lo ha, la richiesta verrà reindirizzata a una pagina di errore o di accesso negato. Potremmo avere diversi filtri per diversi livelli di accesso (es. pagine accessibili solo a amministratori e venditori). Fase 1: Struttura del Database (se non già definita completamente) Definire le tabelle necessarie per prodotti, utenti, e ordini. Stabilire le relazioni tra queste tabelle (es. un prodotto può essere presente in più ordini, un ordine è effettuato da un utente). Definire i vincoli di integrità referenziale (chiavi esterne, ON DELETE CASCADE/RESTRICT). Fase 2: Entità Java (Classi) Creare le classi Java corrispondenti alle tabelle del database (Prodotto, Utente, Ordine, DettaglioOrdine, ecc.) con i relativi attributi (campi) e metodi getter/setter. Fase 3: Data Access Objects (DAO) Creare le interfacce e le implementazioni dei DAO per ogni entità. Questi oggetti conterranno i metodi per interagire con il database (inserire, leggere, aggiornare, eliminare record). ProdottoDAO UtenteDAO OrdineDAO DettaglioOrdineDAO (per gestire le righe all'interno di un ordine) Fase 4: Servlet per la Gestione del Catalogo Creare una o più servlet per gestire le operazioni sui prodotti: Una servlet per mostrare la lista dei prodotti (con possibilità di modificare/eliminare). Una servlet per mostrare il form di inserimento di un nuovo prodotto e processare l'inserimento. Una servlet per mostrare il form di modifica di un prodotto esistente (precompilato) e processare l'aggiornamento. Una servlet per gestire l'eliminazione di un prodotto. In queste servlet, utilizzeremo i metodi del ProdottoDAO per interagire con il database. Implementare la logica per mantenere l'integrità referenziale (es. controlli prima di eliminare un prodotto). Fase 5: Servlet per la Visualizzazione degli Utenti Creare una servlet per recuperare tutti gli utenti dal database tramite l'UtenteDAO. Creare una pagina JSP per visualizzare la lista degli utenti e i loro dati. Fase 6: Servlet per la Visualizzazione degli Ordini Creare una servlet per recuperare gli ordini dal database tramite l'OrdineDAO (potrebbe essere necessario recuperare anche i dettagli degli ordini tramite il DettaglioOrdineDAO). Implementare la logica per: Visualizzare tutti gli ordini. Filtrare gli ordini per cliente (richiederà un input per selezionare il cliente). Filtrare gli ordini per intervallo di date (richiederà due input per le date). Creare una o più pagine JSP per visualizzare gli ordini in base ai criteri selezionati. Fase 7: Implementazione del Controllo Accessi (Filtri) Creare un filtro Servlet (es. AdminFilter). Configurare il filtro nel file web.xml per intercettare le richieste alle URL delle pagine amministrative. Nel metodo doFilter del filtro: Recuperare l'utente dalla sessione. Verificare se l'utente ha il ruolo di amministratore. Se sì, consentire l'accesso alla risorsa successiva nella catena (la servlet/JSP richiesta). Se no, reindirizzare a una pagina di errore di accesso negato. Fase 8: Pagine JSP (Viste) Creare le pagine JSP necessarie per: L'inserimento e la modifica dei prodotti (form). La visualizzazione della lista dei prodotti. La visualizzazione della lista degli utenti. La visualizzazione degli ordini (con le opzioni di filtro). La pagina di errore di accesso negato. Fase 9: Test Testare accuratamente tutte le funzionalità per assicurarsi che funzionino come previsto e che l'integrità referenziale sia mantenuta.
